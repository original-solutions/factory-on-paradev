# Field lessons

Lessons that make the next `/factory` run better. Skill process only.

1. **Leave the worktree before removing it.** Symptom: after `git worktree remove`, every later command fails with "Unable to read current working directory". Cause: the shell's cwd was the removed worktree. Default: `cd` to the primary checkout (or `/tmp`) in the same command as the removal, and run anything that follows from there.
2. **Have correctness check the contract against the doc it was derived from.** Symptom: the code matches the contract on every row, yet the feature cannot work (a state that is entered and never left, a resource taken and never released). Cause: the issue pointed at a design doc, the orchestrator derived the detailed contract from it, and reviewers only compared code to contract. Default: when the contract fills in detail an issue left to a referenced doc, give the correctness reviewer the doc section and ask whether its prose requires anything the contract cannot express. Put the resolved gap on the receipt.
3. **Never resume the maker while the mutating reviewer is running.** Symptom: a reviewer's temporary mutation ends up compiled into the maker's run or committed, or the maker's edit is wiped by the reviewer's `git checkout`. Cause: both work in the same worktree. Default: hold every finding until the mutating reviewer reports a clean `git status`, then send one combined list. Give read-only reviewers committed content only (`git show HEAD:<path>`).
4. **Run live and contract checks from a separate detached worktree at the branch tip.** Symptom: the orchestrator's own verification builds a reviewer's mutation, or blocks on the reviewer's cargo lock. Default: `git worktree add --detach <path> <branch>`, its own target directory, remove it after.
5. **Two issues in flight: the second to land merges the base in first.** Symptom: the second PR conflicts on the files every module touches (the crate root, the lockfile, the README). Default: when the first merges, have the second maker `git merge origin/<base>` and rerun the suite before its next review cycle, so reviewers and the gate see the merged tree.
6. **An issue whose criteria span two modules is two issues.** Symptom: an issue's acceptance criteria mix a self-contained unit with wiring that depends on an unbuilt issue. Default: stop `needs-info` and name the split; when running by hand as orchestrator, file the unit as its own issue, point the original at it, and release the original.
7. **Wait for the mutating reviewer's report, not for a clean worktree.** Symptom: the reviewer's flake check shows failures in tests it never saw, or the maker's new commits appear mid-review. Cause: the reviewer's mutation script finished and restored the tree, the orchestrator resumed the maker, and the reviewer was still running its repeat-run checks. Default: resume the maker only after the reviewer's final report arrives. Tell the reviewer to run its mutations in the foreground inside its own turn and report once; a reviewer that leaves a script in the background and stops may never come back.
8. **A reviewer or maker kills only processes it can attribute.** Symptom: another project's tests on the same machine fail for no reason. Cause: the suite under test used a generic helper (`sleep 30`), and a cleanup step killed every process matching it, including other sessions' helpers. Default: give the suite's long-running helpers a distinctive marker (an unusual duration or argument), and in every maker and reviewer brief say: check for strays by that marker, and never kill a process you did not start (check its parent and working directory first).
9. **One failure in fifty is a flake to fix, not noise.** Symptom: a reviewer reports a single unexplained failure across many repeat runs of unchanged code. Default: treat it as a blocker, have the maker find the cause (a parallel test, an inherited file handle, a timing bound), and verify with 30 or more consecutive runs at the final commit before shipping.
10. **Give the mutating reviewer its own detached worktree.** Symptom: the maker sits idle for the whole mutation pass, or lessons 3 and 7 are broken to save time. Default: the reviewer runs `git worktree add --detach <path> <tip>` from the maker's worktree, mutates only there, and removes it at the end. The maker may then be resumed while the reviewer runs, and the reviewer's findings apply to the tip it copied.
11. **An "unverified" note about an outside system is a live check for the orchestrator, not a nit.** Symptom: a read-only reviewer writes that nothing in the repo shows what the outside system returns for a retried call, and files it as a nit. Cause: reviewers and makers only have fakes, and the fake was written from an assumption. Default: when a retry or resume path depends on how an outside system treats a repeated call, run that call twice against the real system before the fix cycle closes, and give the maker the exact responses.
12. **Budget the mutating review, or it becomes the longest step.** Symptom: a testing review runs for an hour or more while everything else is approved and waiting. Cause: an open-ended mutant list, the whole suite and a rebuild per mutant, flake loops and gate runs the maker and orchestrator already do, a pass on every cycle, and one long foreground script that cannot read a message. Default: follow "Testing review budget" in `review.md`. This replaces the "run the mutations in one foreground script" advice in lesson 7 with one mutant per command.

13. **A turn that ends early looks like a failed run to the factory.** Symptom: the issue goes to `stuck` with "the session ended without a result line" and the session then opens a pull request anyway. Cause: the session started a reviewer in the background and ended its message while waiting; the host woke it later, after the factory had already released the issue. Default: every subagent runs in the foreground inside one turn, and the only messages that end a turn are the three result lines.
13. **Name the branch, not a sha, when a reviewer makes its own worktree.** Symptom: the reviewer's brief pins the sha from the maker's report, but the maker added one more test and fix pair after that line was written, so the pinned sha is one behind the tip. Default: resolve the tip yourself with `git rev-parse <branch>` at dispatch, after your own test run, and put that in the brief; tell the reviewer to say which commit it reviewed.
14. **A message to a finished maker runs in the background; wait for it inside the turn.** Symptom: after sending a fix list to the maker, nothing blocks and the turn is about to end without a result line. Cause: a resumed subagent returns at once and reports later. Default: after the send, poll in one foreground Bash loop (HEAD plus `git status --porcelain` unchanged for about 2.5 minutes, new commits past the old tip, 9 minute cap) and repeat it until the maker's completion arrives. For anything that must be foreground, spawn a fresh Agent with the packet instead of resuming.
15. **A detached review worktree needs its own copy of the dependency directory.** Symptom: tests in the detached worktree fail with "facade root not set" or "Target class [config] does not exist" while the maker's tree is green. Cause: a symlinked `vendor` makes the test runner resolve the app root through the link. Default: copy `vendor` (and dump the autoloader), symlink only `node_modules`, and run the suite once for green before handing it to the mutating reviewer.
16. **A host attribution reminder does not override the no-trailer rule.** Symptom: the harness asks for a co-author trailer or PR footer, and the first commit carries one. Cause: the reminder arrives after the skill and the user's global rules, which both ban trailers. Default: write every commit message and the receipt without trailers from the first commit; if one slips in, amend before the first push.
17. **Check that the worktree is at the base tip before reading code.** Symptom: the worktree the factory made holds only an old commit, and the code the issue depends on is missing. Cause: it was cut from a stale local base branch. Default: at Isolate, `git fetch` and compare `HEAD` with `origin/<base>`; when `HEAD` is an ancestor and the tree is clean, `git merge --ff-only origin/<base>` before provisioning, and say so on the receipt.
18. **Run the changed feature once through its real entry point with realistic data before Ship.** Symptom: every test and every reviewer passes, and the first real request fails. Cause: unit tests called the class directly and skipped a framework layer that validates or serialises the result, and the test data never held the commonest real value. Default: for a UI or API criterion, start the app, seed data copied from the contract's own examples, and load the page or call the route; turn whatever breaks into a failing test first.
